# GreenLint v1.2 案例

案例来自用户提供的 `GreenLint_演示包_v1.2.zip`，以其中 `03_开发/ui.html` 的 `SAMPLES` 和 `使用说明.txt` 为准。`samples_master.xlsx` 是未填写的采集模板，不是这三个案例的数据源。包内没有原始广告图片、商品链接或采集日期，因此按文案展示，不生成或冒充原图坐标。

| 案例 | 市场 | 包内结果 | 展示重点 |
| --- | --- | --- | --- |
| Apple Watch | 英国 | 1 处高风险 | `Carbon Neutral`；核算范围、实际减排与抵消的关系需核实 |
| Eco Dog Bed | 英国 | 5 处高风险 | 再生材料比例、泛化环保表述、环保系列入选标准；同一句可匹配多条规则 |
| Copier Paper | 欧盟 | 0 处风险 | 材料与比例、FSC 编号线索；纸张颜色比较不误判为环保性能比较 |

首页原水杯案例下面提供三个案例入口。进入后可选中文案中的风险句、查看风险和规则说明；两个负面案例接入原庭审接口，固定演示下每项风险均可完成四次控辩与一次裁判。实时模式沿用配置的模型生成庭审；案例审核本身始终为预设本地结果。改写删除选中风险句，复核剩余文案，原文单独保留。正面案例不制造风险或争议入口。

## 数据与边界

- `backend/app/data/examples/greenlint-v1.2.json` 保留三段完整原文、市场、品类、预期结果、原压缩包 SHA-256 和数据源路径。
- `greenlint-v1.2-rules.json` 保留九条包内规则。运行时按规范化 JSON 的 SHA-256 校验，避免换行格式改变造成错误。
- `services/greenlint.py` 只为这些固定案例及其删除式改写复现包内的分句、关键词和上下文门槛；没有执行压缩包里的启动脚本、服务、工具或 AI 调用代码。
- LR 编号是包内匹配规则。其条号、日期和行业适用范围没有在本次独立复核，单独在“包内演示规则说明”显示；英国风险与庭审引用现有的 G1/G2 CMA 指引，不把 EU 条款直接作为英国法律依据。
- `Carbon Neutral` 一词本身不能证明使用了抵消。风险说明要求补充核算依据，不断言品牌违法。
- Copier Paper 的 0 风险仅复现欧盟演示规则的结果，不验证 100% 再生材料或 FSC 编号真伪，不构成投放批准。换用英国规则不会保证相同结果。
- 实时图片上传仍只支持既有英国水杯范围；欧盟和新类别仅用于这三个案例，并未扩展实时规则覆盖。
- 第一版界面及 `ui-v1` 标签保持不变，原水杯案例仍可使用。

## 接口

- `GET /api/demo-cases`：案例目录。
- `POST /api/demo-cases/{case_id}`：幂等安装并打开 `apple-watch`、`eco-dog-bed`、`copier-paper`。
- 后续复用审核、改写、异议、庭审与 JSON 导出接口，结果写入 SQLite，可在刷新与重启后读取。

## 验证

后端测试覆盖三例原文与市场、1/5/0 结果、重复打开、恢复、六项风险的全部庭审步骤、错序与重复请求、删除复核、稳定 ID 不冲突、正例不借用英国规则、未知案例与实时模式不调用模型。

`tests/greenlint-browser.cjs` 检查三个入口、文本选择、规则、改写、庭审、刷新、报告下载和四种屏幕宽度。隔离演示服务启动后，设置 `VITE_BACKEND_URL` 启动单独的 Vite 服务，设置 `APP_URL` 和 `API_PROXY_URL` 运行脚本。这样下载也通过正确的演示后端，不触及实时供应商。
